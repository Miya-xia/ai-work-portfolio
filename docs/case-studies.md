# 两个案例：过程、贡献、证据

## 01 / AI 辅助交互网站

### 问题

线性材料难以同时呈现过程、成果和可选择的讲述顺序。希望做成可探索的网站，并保留按章节顺序演示的方式。

### 我的贡献

确定受众和讲述结构；提供视觉方向；指出重复、过空、未经授权改写原文等问题；给出具体反馈并检查页面结果。

### AI 辅助

把要求实现成 HTML、CSS、JavaScript；辅助修改样式、整理交互、编写技术检查和部署配置。代码本身不是“本人独立手写”的证明。

### 实现结果

柜门开场、跳过与重播；七个可点击物件；目录与键盘导航；窄屏布局；本地草稿和离线审核 HTML 导出。本仓库中的实际代码和演示是证据，不以未记录的效率增长代替证据。

### 公开处理

公开版独立搭建，重写案例摘要，移除原材料、内部链接和非公开图片。用原创几何 SVG 和虚构内容演示交互。不把“页面里不显示”当作脱敏——公开仓库与部署目录都要检查。

## 02 / 客诉回复的人工审核工作流

### 问题

常规回复与需要人工优先跟进的诉求不能混在一起。让情绪线索、风险判断、回复草稿和人工把关在同一流程中更容易检查。

### 我的贡献边界

业务侧参与场景梳理、频率 / 语气 / 表情线索的表达、风险分级要求、话术检查和人工审核。团队的模型、工程或生产交付不计为个人独立成果。

### 当前公开演示

五个可点步骤：接收消息、理解情绪、风险分级、准备草稿、人工审核。三个固定虚构案例，不做实时推理。中高风险草稿可修改并导出 HTML，导出文件还能离线继续修改与保存。

### 不能由这个页面推出的结论

- 不能据此声称已经生产上线、接入真实账号或自动发送。
- 不能声称风险判断准确率、客诉覆盖率或节省时间。
- 没有真实客户验证；风险与回复仅用于说明协作逻辑。
- 表情和消息频率不能单独决定风险，安全相关诉求应优先人工跟进。

## 面试演示建议

1. 用柜子介绍组织结构，说明为什么选择这种形式。
2. 打开迭代页，说明一次具体反馈如何变成可验证的改动。
3. 打开人工审核工作流，切换风险与步骤。
4. 修改一条虚构回复并导出 HTML，说明交付与人工把关。
5. 打开代码、测试和发布记录，主动说明 AI 辅助范围及尚未验证的部分。
